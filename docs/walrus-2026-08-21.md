## Decisions

- Python-first, TypeScript parity later — listed platforms have mature async Python SDKs; the kernel is pure and portable
- Immutability via `frozen=True, slots=True` dataclasses rather than runtime policing
- Identity-free `Dispute` type — neutrality by construction, not by intention
- SHA-256 tie-break — deterministic, symmetric, status-free
- RAROC = (V×P)/C adopted as the gap-prioritization metric for this project
- Public repo, matching seva/hearth-interface visibility convention

## Alignment

- epistegrity pinned at 8e89b07 (`.epistegrity-version`); METHODOLOGY.md verbatim; no deviations declared
- AGENTS.md behavioral rules enforced in code by `BoundaryConstraints`
- Post-phase audit is a gate, not a suggestion
- Commit identity: `seva <seva@users.noreply.github.com>` (GH007 constraint)

## Tradeoffs

- Marker-based unvalued-text classification accepted as crude but deterministic baseline; cost: misclassification on novel phrasing; reason: any learned classifier must be memoized by content hash anyway, and `classify` is a pure swappable function
- `pytest-cov` added to dev extra mid-audit; cost: one more dependency; reason: coverage is a mandated audit step

## Alternatives

- TypeScript-first seeding — rejected: platform SDK maturity and iteration speed favor Python; TS parity stays a planned track
- Fixing all RAROC gaps before creating the GitHub repo — rejected: the issue record is prerequisite to everything else (RAROC 5.0 vs ≤1.6)
- WaLRuS per commit instead of per session — rejected: METHODOLOGY excludes session logs by design
